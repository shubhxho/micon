# Data-Value Uplift Brainstorm

Short scratchpad for ideas that lift the dataset's commercial value beyond
what the current pipeline already produces. Each item lists the **value
lever**, **est. effort**, and **est. cost delta** vs. today.

Just-shipped (this branch) is at the bottom for reference.

---

## Tier A — high value, low effort

### A1. Quality-conditional escalation
Run the cheap-tier lineup first. Only escalate to a premium model
(Claude / GPT-4) when the cheap models *disagree* on the primary axis
(`sequence_type`, `pathology.found`). On a 1,105-study run, ~85% of
series are unambiguous and never need the expensive path.

- Lever: same buyer-grade quality on hard cases, cheap-tier price on easy ones.
- Effort: ~1 day; gating logic lives in `merge_annotations`.
- Cost delta: -60 to -80% vs. running premium on every study.

### A2. Per-study confidence score
Aggregate the existing `models_agreeing` / `models_total` + `sequence_agreement`
into a single `study_confidence` number on the manifest. Buyers filter on
"high-confidence subset" without rerunning anything.

- Lever: enables tiered pricing (high-confidence subset = premium SKU).
- Effort: <1 day.
- Cost delta: $0.

### A3. Reasoning tokens
Kimi VL Thinking, Qwen3 VL, Gemini 2.5 — all expose explicit
reasoning/thinking tokens. Capture them into `per_model[…].reasoning` so
buyers training models can see *why* the annotator chose a label, not
just the label. This is the single most-asked-for feature on
HuggingFace medical-imaging discussion threads.

- Lever: differentiates from every existing dataset on the market.
- Effort: 1-2 days; need to extract `reasoning_content` from the OR response.
- Cost delta: marginal (reasoning tokens cost the same).

### A4. Prompt caching
OpenRouter supports Anthropic-style `cache_control` markers on long
system prompts. The `ANNOTATION_PROMPT` is ~2k tokens and identical for
every series (~3,400 calls). Marking it cached drops cost ~50% on the
prompt portion.

- Lever: pure cost cut, no quality loss.
- Effort: half day; one decorator on the prompt block.
- Cost delta: -25 to -40% on annotation stage.

## Tier B — medium effort, high differentiation

### B1. BiomedCLIP embeddings + dedup index
Microsoft BiomedCLIP gives a 768-D medical-imaging embedding per
montage. Index them in a parquet column → buyers query
"give me the 200 studies most similar to this one." Also flags
near-duplicate studies (same patient, different accession) so the
manifest can dedup or expose them as a "multi-encounter longitudinal" SKU.

- Lever: opens "similarity search" + "longitudinal" SKUs.
- Effort: 2-3 days; one Modal class around the model.
- Cost delta: +small one-time GPU cost; saves on storage if dedup runs.

### B2. DSPy-optimized annotation prompt
Treat `ANNOTATION_PROMPT` as a DSPy `Signature`, run BootstrapFewShot
against a held-out validation set (radiologist-labeled subset), let
DSPy pick exemplars + tune the instruction. Reproducible quality
delta on the cheap models without changing the model.

- Lever: closes the gap between cheap tier and Claude on hard cases.
- Effort: 2-3 days, mostly building the validation set (50-100 studies).
- Cost delta: +one-off optimization run, then -0.

### B3. Structured outputs everywhere
Already started (`json_schema` in `_call_model`). Define one
`AnnotationSchema` JSON Schema and pass it on every cheap-tier call.
Drops parse-failure rate from current ~3-5% to ~0, saving the retry/
regex-extract path.

- Lever: cleaner data, less wasted spend.
- Effort: half day; schema export already lives in `src/schemas/`.
- Cost delta: -3-5% (parse-failure retries gone).

### B4. Croissant 1.0 + DataCite signing
We already emit Croissant + DataCite blocks. Get the dataset
*signed* (DataCite DOI minting + W3C-PROV chain-of-custody). HF
treats signed datasets as "verified" — buyers Google "verified
medical imaging dataset" and we're top of the list.

- Lever: search rank + buyer-trust signal.
- Effort: 2 days; bureaucratic, not technical.
- Cost delta: ~$200/yr DOI fee.

## Tier C — bigger bets, larger differentiation

### C1. Pre-computed segmentation masks
Already shipped for SynthStrip + SynthSeg + MONAI WMH (just merged in
this branch). Next: per-finding 2D masks generated by the annotator
model (Kimi VL Thinking can do bounding boxes). Adds pixel-level
labels at zero marginal cost.

- Lever: doubles the buyer base (segmentation models can train on this).
- Effort: 3-5 days.

### C2. Multi-modal fusion (DICOM SR + report text)
Most studies have an associated radiology report on the original
DICOM SR pages. Extracting the report text via Tesseract + LLM
post-processing gives a `findings` + `impression` string per study —
which is exactly what RadGraph / RadGraph-XL benchmarks need.

- Lever: makes the dataset evaluable on benchmark leaderboards.
- Effort: 5+ days (OCR is finicky).

### C3. claude-flow multi-agent refinement
The user mentioned this. claude-flow.ai is a multi-agent orchestrator
that runs separate agents for {extract, annotate, critic, synthesize}
with a shared scratchpad. Expensive but gives the highest-quality
single-pass output for a "premium SKU" tier.

- Lever: enables a premium-SKU tier (50x base price, 1% of studies).
- Effort: 1 week; new dependency, needs sandboxing.
- Cost delta: +significant per-study, but only on premium SKU.
- **Status:** *not yet adopted — pending sign-off on adding the dep.*

## Just shipped (this branch)

- MODELS dict split into cheap/premium tiers; Kimi VL is the cheap default.
- Synthesis default flipped from Claude → Kimi.
- `Annotator` is a Modal `@app.cls`: warm-container reuse of OpenAI client + module imports across 32 concurrent calls.
- OpenRouter `extra_body` plumbing in `_call_model`: cheapest-provider routing (`provider.sort=price`), auto-failover model chain (`models=[…]`), and structured-output (`response_format`) wired in.
- Synthesis call uses an OR-side cheap-tier fallback chain.
- Per-model + per-series records carry tier telemetry (`tier`, `tiers_used`, `premium_used`).
- MONAI segmentation pre-computation cherry-picked onto main.
